# Extensive review coverage

Default to the whole requested course or module. Honor a narrower user request.
Extensive means checking the surfaces and decisions that support its promise.
The number of agents, findings, pages or words does not establish that coverage.

## Inventory before dispatch

List lessons, outcomes, prerequisites, worked examples, visual types, assessment
families, project stages and transfer tasks. Include titles, introductions,
navigation, labels, hints, feedback, error/empty states, summaries and exported
instructions. Include narration/transcripts when supplied. Preserve which text
was rendered, read only in source or inaccessible to the reviewer.

Use an ordinary table in the run note, with stable unit/surface names:

| Unit or surface | Outcome / claim | Teaching | Editorial | Assessment | Visual / access | Behavior / evidence | Next work |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Actual unit name | Actual promised ability | Status + evidence | Status + evidence | Status + evidence or n/a | Status + evidence or n/a | Status + evidence | Owner / action |

Statuses are inspected, sampled, blocked and uninspected. Use n/a with a reason
only when a dimension doesn't apply. Record what an inspected cell establishes;
reading source doesn't establish browser behavior. Counts use the original
inventory as the denominator. Add discovered surfaces; don't remove failed ones.

## Required passes for the included scope

- **Promise and progression:** connect every outcome to preparation, a decision,
  feedback and independent application. Check transitions and prerequisites.
- **Complete copy review:** read every unit and its instruction/feedback copy,
  including optional reveals. Use all editorial lenses; record inaccessible
  narration or conditional text instead of skipping it silently.
- **Assessment and difficulty:** for each assessment family, check a meaningful
  wrong answer, a sound answer and a valid alternative where the contract allows
  one. Review grading, feedback, repair, assistance and freshness. Audit advanced
  projects even when the existing learner runner only handles early chapters.
- **Project usefulness:** examine what the learner produces, what runs, what is
  merely a demonstration, whether decisions matter and whether another person
  could reproduce the result. Include budget constraints and defensible tradeoffs
  when they're part of the subject. Do not demand implementation for every topic.
- **Visual and interaction:** inspect each distinct visual and layout in its
  teaching context, including consequential wrong/correct and pending/committed
  states. Apply the viewport/keyboard/zoom/motion matrix from roles.md to the
  essential workflows. State any state/device sampling explicitly.
- **Persistence and evidence:** check first-work retention, revision, navigation,
  reload, stale feedback, errors and exports through the existing tooling.
  Include conflicting edits or sandbox controls where the course uses them.
- **End-to-end attempt:** use retained exact-build attempts when they answer the
  question. Add fresh attempts for unmet outcomes within the actual provider and
  resource bounds. Keep every unattempted advanced route visible in the ledger.

Exhaustive UI combinations aren't required. Choose representative states with a
reason, include known risks, and preserve the distinction between inspecting a
family and trying every instance. A conceptually broken assessment still needs
attention even when every UI transition passes.

## Resume without losing the standard

At each substantial pass, save coverage, evidence, unresolved findings, usage,
the next action and the current subject identity. If the course changes, identify
affected rows and recheck them. Do not label changed copy reviewed because its
previous version passed. If a path is blocked, review other accessible material.

A budget stop returns a partial audit. The remaining work and its reason are
part of the deliverable; there is no silent reduction to a sampled review.
Report prioritized improvements in the response and all verified findings in
the artifact. Do not manufacture a fixed number of defects or expand the course
merely to make the review look extensive.
